# Security policy

Semantic Canvas has separate local, public sandbox, and company (`team` / `gateway`) modes. Local mode binds to loopback by default and its role picker simulates policies; do not expose local mode directly as a shared service without `SC_SANDBOX_MODE=true`. Company mode (`SC_MODE=team`) requires HTTPS, OpenID Connect, and explicit server access bindings (`SC_ACCESS_PATH`). It enforces `viewer` / `editor` / `admin` roles, source allowlists, CSRF tokens, and server-selected row principals. Missing company authentication configuration stops startup; it never falls back to local mode.

Company mode is not an independently security-audited multi-tenant SaaS distribution; run one workspace per deployment. See [self-hosting](docs/self-hosting.md) for configuration and limits:
- **Sessions:** Opaque `Secure; HttpOnly; SameSite=Lax` `__Host-sc_session` cookies expire after one hour by default (`SC_SESSION_SECONDS`). Sessions are held in memory by default (cleared on restart) or optionally persisted encrypted at rest (`AES-256-GCM`, `0600` file mode in `SC_DATA_DIR/sessions.json`, with refresh tokens encrypted) when `SC_SESSION_SECRET` and `SC_DATA_DIR` are configured. When the identity provider issues a refresh token, open sessions are re-checked every five minutes by default (`SC_SESSION_RECHECK_SECONDS`) and terminated if access was revoked or changed.
- **SCIM 2.0 & Deprovisioning:** Optional SCIM 2.0 provisioning (`/api/scim/v2`, enabled only when `SC_SCIM_TOKEN` is set) persists provisioned users and groups to `SC_DATA_DIR/scim.json`, immediately revokes open sessions on user deactivation or deletion, and blocks subsequent OIDC sign-in or refresh when `active: false`.
- **MCP & AI Boundaries:** Authenticated Remote HTTP MCP (`POST /api/mcp`) requires a verified session and enforces caller RBAC and RLS; local stdio MCP (`npm run mcp`) is for single-user local setups only. In company modes (`team` / `gateway`), custom `ai.baseUrl` endpoints reject loopback, RFC1918 private, CGNAT, and cloud link-local/metadata addresses unless `SC_ALLOW_PRIVATE_AI_URL=true` is explicitly set by the operator.
- **Public Sandbox (`SC_SANDBOX_MODE=true`):** Isolates visitor-uploaded spreadsheets per opaque `HttpOnly` session cookie (`sc_sandbox_sid`), blocks shared dashboard/library/activity mutations, source/AI-key writes, MCP, SCIM, and `/api/agent/questions`, redacts server paths, and enforces origin + proxy-aware rate limits.
- **Shared Source Scope:** Within a workspace source, saved dashboard text and filter defaults are visible to authenticated users permitted on that source; there are no per-document private ACLs.

Use the included HTTPS proxy or a private upstream behind your own TLS proxy. Protect the persistent data volume and server environment. Full volume backups contain secrets; logical library backups contain authored document content and discussion threads. Logs are allowlisted and omit payloads and credentials; operators must also configure safe logging at proxies and collectors. Operational audit events are not a tamper-proof compliance ledger.

Semantic model files and source configuration are trusted administrator inputs. Workspace administrators can configure connections and upload semantic models; this is a privileged operator role. Metric expressions can contain SQL. Connection credentials stay on the server; always use read-only warehouse credentials. AI is optional and sends the requested document context and scoped query results to the configured provider. Images are omitted from canvas-chat context.

For a security vulnerability (including authentication, session/sandbox isolation, row-level security, SSRF, or credential handling), use GitHub private vulnerability reporting or contact the repository maintainer privately through GitHub—do **not** open a public GitHub issue containing exploit details, credentials, private paths, or customer data. Include the affected commit/version (`v0.3.6`), configuration mode, minimal reproduction, observed impact, and a sanitized fixture.

This is an open-source project; no formal SLA response-time guarantee is offered. Supported releases and security fixes are recorded in [CHANGELOG.md](CHANGELOG.md). Prefer current dependencies, a committed lockfile, and the supported Node.js versions in [package.json](package.json).
